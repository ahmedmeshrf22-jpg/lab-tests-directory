V106 FINAL CHECK / LAB OPERATOR UX

1) Lab operator UI simplified to three icon states only:
   - New orders
   - In progress
   - Sent results
2) Lab receipt shows patient/order/tests/clinic notes only. No price, total, discount, payment or remaining amount is rendered.
3) Lab orders use the same clinic orders as the single source of truth; old lab_queue app dependency removed.
4) Live Firestore listener keeps the lab screen updated while open.
5) Dedicated lab-only Android notification channel for new test orders.
6) FCM token is re-registered after every sign-in so account switching does not leave the device token on the wrong user.
7) Native Android JobScheduler provides a backend-free background fallback check every ~15 minutes for the signed-in lab_operator account only.
8) FCM remains supported for instant background delivery if the existing Firebase notification functions are deployed.
9) Recent-order query is limited to 200 records for normal operation, with a compatibility fallback if the collection-group index is not deployed.
10) Unused KSP root plugin declaration and unused Room/Retrofit/Moshi/logging app dependencies removed to reduce build fragility and package complexity.
11) Existing signed mandatory updater remains signature-verified and SHA-256 verified.
12) Firebase project/package configuration checked locally: tahalil-alakkad / com.aistudio.labtestsdirectory.egypt.

Important operational limitation:
Live Firebase server/rules/functions deployment cannot be proven from source files alone. V106 is designed to work without a new backend deploy for the lab order list and local/background fallback notifications. Instant push while the app process is fully stopped still depends on the already-deployed Firebase Functions/FCM environment.
